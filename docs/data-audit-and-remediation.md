# Data audit and remediation — Eastern Pacific reef dataset

**Date:** 2026-09-20
**Scope:** the training, validation and evaluation material developed for the
Utría / Eastern Pacific reef study, imported from Google Drive.
**Status:** audit complete; leakage-free splits built and verified; retraining
run; baseline comparison scored on the held-out `test` split.

---

## 1. Summary

The imported work builds a 13-class fish *species* detector on 790 annotated
frames drawn from two reef video transects. The audit found three problems that
invalidate the reported results, and several smaller defects.

| # | Finding | Severity |
|---|---|---|
| 1 | Training and validation sets were **identical** | Invalidating |
| 2 | 60% of annotations are a `not_defined` catch-all class | Invalidating for species work |
| 3 | Four species have 1–2 annotated boxes in total | Invalidating for species work |
| 4 | 230 annotated frames silently discarded | Major |
| 5 | Baseline and trained model compared on different metrics | Major |
| 6 | `evaluar_linea_base.py` reads a path that does not exist | Major |
| 7 | Hardcoded Windows absolute path in `dataset.yaml` | Minor |
| 8 | Evaluation logic duplicated across two scripts | Minor |
| 9 | Re-introduces an AGPL dependency the repo had moved away from | Policy |

The reported **mAP50 of 0.9373** is not a measure of model performance. It was
computed on the training images themselves.

## 3. Findings

### 3.1 Train and validation were the same set — *invalidating*

`dataset.yaml`, generated by `preparar_entrenamiento.py:94`:

```yaml
train: images/train
val: images/train
```

`runs/detect/cfd_pacifico/args.yaml` confirms the run used `split: val` against
that file. Every number in the run — mAP50 0.9373, mAP50-95 0.7249, precision
0.8908, recall 0.6365, and all PR/F1 curves and the confusion matrix — was
measured on the 560 images the model had just memorised.

The code comment (`# Usamos las mismas para la base inicial`) shows this was a
deliberate bootstrapping shortcut, not an accident. It was never undone.

A second, subtler leak would remain even with a random split. Frames are three
seconds apart on a continuous transect, so adjacent frames are near-duplicates.
Random assignment puts near-identical images on both sides of the boundary,
which inflates scores again. The split must be **temporally grouped**.

### 3.2 Sixty per cent of annotations are a catch-all class — *invalidating for species work*

| Class | Species | Boxes | Share |
|---|---|---:|---:|
| 12 | **`not_defined`** | **1,070** | **60.4%** |
| 11 | *Thalassoma lucasanum* | 399 | 22.5% |
| 0 | *Azurina atrilobata* | 125 | 7.1% |
| 10 | *Stegastes acapulcoensis* | 67 | 3.8% |
| 3 | *Diodon holocanthus* | 33 | 1.9% |
| 2 | *Cephalopholis panamensis* | 24 | 1.4% |
| 5 | *Haemulon maculicauda* | 17 | 1.0% |
| 9 | *Scarus ghobban* | 17 | 1.0% |
| 1 | *Bodianus diplotaenia* | 14 | 0.8% |
| 4 | *Epinephelus labriformis* | 2 | 0.1% |
| 6 | *Holocanthus passer* | 1 | 0.06% |
| 7 | *Johnrandallia nigrirostris* | 1 | 0.06% |
| 8 | *Lutjanus argentiventris* | 1 | 0.06% |

Training a class whose definition is "we could not tell" teaches the model to
emit that class for anything ambiguous, and it dominates the loss at 60% of
boxes. Removing it leaves **701 species-labelled boxes, 75% of which are two
species**.

### 3.3 Four species have one or two boxes — *invalidating for species work*

*Holocanthus passer*, *Johnrandallia nigrirostris* and *Lutjanus
argentiventris* have **exactly one annotated box each**; *Epinephelus
labriformis* has two. These cannot be learned, and cannot be evaluated: with
train and val identical, the model was scored on the same single box it trained
on.

Per-video breakdown compounds this. Only six labels appear in both transects
(`not_defined`, *Thalassoma*, *Azurina*, *Stegastes*, *Diodon*,
*Cephalopholis*). *Scarus* and *Lutjanus* occur only in `reef_01`;
*Haemulon*, *Bodianus*, *Epinephelus*, *Johnrandallia* and *Holocanthus* only
in `reef_02`. Any split that respects video boundaries can therefore evaluate
at most five real species.

### 3.4 Two hundred and thirty frames were silently discarded — *major*

`preparar_entrenamiento.py:81` writes a label file only when `lineas_yolo` is
non-empty:

```python
if lineas_yolo:
    shutil.copy(img_path, os.path.join(images_output, filename))
```

790 annotated frames became 560. The 230 frames with no fish were dropped.

Those frames are the dataset's only negative evidence. YOLO treats an image
with an empty or absent label file as a background example, and uses it to
learn what *not* to fire on. Discarding them removes the model's only training
signal against false positives — which is precisely the error mode the study
sets out to quantify. They also made the reported precision optimistic, since
the model was never shown, or scored on, empty water.

### 3.5 Baseline and trained model are compared on different metrics — *major*

- `procesar_y_evaluar.py` reports precision / recall / F1 at a fixed
  `conf=0.25`, `IoU=0.50` for the RF-DETR baseline.
- `obtener_datos.py` reports ultralytics' **mAP50** for the trained model.

These are not comparable. mAP integrates precision over all recall levels;
F1 at a fixed threshold is one point on that curve. Reporting "baseline F1 =
x%" beside "our model mAP50 = y%" compares two different quantities.

Both models must be scored with one metric, computed by one piece of code, on
the same held-out images.

### 3.6 `evaluar_linea_base.py` reads a non-existent path — *major*

Line 24 sets `images_dir = "./mis_fotos"` (underscore). Every other script uses
`"./mis fotos"` (space). The per-image `os.path.exists` check therefore fails
for all 790 frames, the loop body never executes, and the script reports
0 TP / 0 FP / 0 FN with precision, recall and F1 all zero — without raising an
error.

`procesar_y_evaluar.py` supersedes this script and uses the correct path.

### 3.7 Smaller defects

- **Windows absolute path.** `dataset.yaml` begins
  `path: C:\Users\Usuario\Downloads\community-fish-detector-main\...`, so the
  file works only on the machine that produced it.
- **Duplicated logic.** `compute_iou` and the TP/FP/FN matching loop are
  copy-pasted verbatim between `evaluar_linea_base.py` and
  `procesar_y_evaluar.py`. Two copies will drift.
- **Inconsistent ground truth.** `procesar_y_evaluar.py` reads the *raw*
  `REEF 1 2.json` rather than the cleaned `REEF_1_LIMPIO.json`. Harmless for
  single-class detection, but a trap once species enter the evaluation.
- **Image size.** `entrenar_peces.py` sets `imgsz=1024`, annotated as required
  by the documentation. That figure belongs to the **yolov12x** model card;
  `best.pt` is 6.28 MB, i.e. yolov8n. Training a nano backbone at 1024 should
  be a deliberate choice, not an inherited constant.
- **Licensing.** The repository moved from YOLO to RF-DETR and marks the YOLO
  path deprecated, partly to leave AGPL behind. `entrenar_peces.py` reintroduces
  `ultralytics` (AGPL), which constrains how resulting weights may be
  distributed. A decision to make consciously.

## 4. Remediation plan

### 4.1 Collapse to a single `fish` class

The dataset cannot support 13-class species detection: 60% of boxes are
unidentified, four species have ≤2 examples, and only five species appear in
both transects.

Collapsing to one class resolves 3.2 and 3.3 at once, because **an unidentified
fish is still a fish**. The `not_defined` boxes stop being unusable noise and
become valid positives. Nothing is discarded: all 1,771 boxes are retained.

It also aligns the work with the repository's actual task — the Community Fish
Detector is a single-class `fish` detector — which turns the study into a
question the data can answer:

> Does domain fine-tuning on Eastern Pacific reef footage improve on the
> general-purpose Community Fish Detector baseline?

The 13-class taxonomy remains in the annotation files and stays available for
descriptive statistics (species composition, relative abundance), which is what
this annotation effort can legitimately support.

*Alternative if species detection is required:* keep the four species with ≥24
boxes and merge the rest into `other_fish` — five classes. Still thin, and
still limited to species present in both transects, but defensible.

### 4.2 Split by contiguous temporal blocks with guard bands

Implemented in `scripts/build_splits.py`. For each video:

1. Order frames by index.
2. Cut into 12 contiguous blocks.
3. Assign whole blocks by a fixed repeating pattern
   `train val train train test train`, so every split draws from throughout
   each dive rather than one stretch of it.
4. Drop a **guard band** of 2 frames either side of every boundary where the
   assignment changes, opening a real temporal gap between splits.

Both transects contribute to all three splits, which avoids trading temporal
leakage for a reef-to-reef distribution shift.

### 4.3 Retain background frames

All 790 annotated frames enter the splits. Frames with no fish receive an empty
label file and serve as background negatives, restoring the false-positive
training signal lost in 3.4.

### 4.4 Single evaluation path

Score the RF-DETR baseline and the fine-tuned model with the same code on the
same `test` split, reporting mAP50 and mAP50-95 alongside precision/recall/F1
at a stated threshold. Extract the shared `compute_iou` and matching loop into
one module and delete the duplicate.

### 4.5 Reserve the test split

`val` guides training and threshold selection. `test` is read **once**, for the
final reported numbers. Every intermediate decision uses `val` only.

## 6. Retraining results

Run with `scripts/train_yolo.py` on `configs/pacifico-fish-1class.yaml`:
yolov8n, 50 epochs, imgsz 640, batch 8, seed 0, MPS, 0.536 h.

`imgsz` is 640 rather than the original 1024. The 1024 was inherited from the
yolov12x model card (3.7) and was never justified for a nano backbone; 640 is
also the resolution the RF-DETR baseline was trained at, which makes the
comparison in 4.4 cleaner. At 1024 with batch 16 the run also exhausts unified
memory on a 16 GB machine and collapses into swap.

### 6.1 Headline numbers

Validation split, 116 images, 232 boxes, `best.pt` (epoch 32):

| Metric | Value |
|---|---:|
| mAP50 | **0.583** |
| mAP50-95 | 0.268 |
| Precision | 0.564 |
| Recall | 0.578 |

Final epoch 50 was worse than the best: mAP50 0.543.

### 6.2 Against the previously reported figure

| | Previous | This run |
|---|---:|---:|
| mAP50 | 0.9373 | **0.583** |
| Measured on | the training images | a held-out split |

The gap is not a regression. It is the size of the error the leak was hiding.

The two runs differ in more than the split — 13 classes at 1024 versus one
class at 640, and background frames now included — so this is not a controlled
comparison. But the confounds work *against* the leaked figure: single-class
detection is a strictly easier task than 13-class, so an honest 13-class score
would be lower still, not higher.

### 6.3 Convergence

Training loss falls monotonically, 7.94 to 3.88. Validation loss bottoms at
**epoch 33** (5.06) and drifts upward thereafter while training loss keeps
falling — the signature of mild overfitting.

| Epoch | Train loss | Val loss | mAP50 |
|---:|---:|---:|---:|
| 1 | 7.943 | 7.402 | 0.099 |
| 10 | 5.041 | 6.083 | 0.469 |
| 20 | 4.621 | 5.367 | 0.557 |
| 32 | 4.231 | 5.319 | **0.591** |
| 40 | 4.054 | 5.476 | 0.573 |
| 50 | 3.875 | 5.389 | 0.543 |

mAP50 peaks at epoch 32 and declines over the final 18 epochs. The 50-epoch
budget is therefore too long for this dataset: the run should stop around epoch
35. Per-epoch mAP is noisy — a 232-box validation set moves several points when
a handful of detections change — so the peak should not be over-read either.

`best.pt` correctly captures epoch 32 rather than the final weights.

### 6.4 Reading these numbers

mAP50 0.583 with mAP50-95 0.268 says the model finds roughly the right fish but
localises them loosely: performance falls away sharply as the IoU threshold
rises. Recall 0.578 means it misses about four fish in ten.

This is a plausible result for 495 training images and 981 boxes of small,
low-contrast underwater targets. It is a starting point, not a finished
detector.

## 7. Baseline comparison on the test split

Scored with `scripts/evaluate.py`, both models through the same ground truth
and the same metrics code (`scripts/detection_metrics.py`), on the `test`
split — 115 images, 369 boxes — read here for the first time. mAP comes from
pycocotools.

### 7.1 Headline

| Model | mAP50 | mAP50-95 | P@0.25 | R@0.25 | F1 |
|---|---:|---:|---:|---:|---:|
| CFD baseline (RF-DETR nano, 640) | 0.172 | 0.054 | 0.193 | 0.287 | 0.231 |
| Fine-tuned (yolov8n, 640) | **0.733** | **0.323** | 0.655 | 0.715 | 0.684 |

Read alone, this says fine-tuning beat the baseline by 4.3× on mAP50. That
reading is wrong, and the next section is the actual result.

### 7.2 The gain is localisation agreement, not detection ability

Recall and precision at conf 0.25, swept across the IoU threshold:

| IoU | Baseline R | Baseline P | Baseline TP | Fine-tuned R | Fine-tuned P | Fine-tuned TP |
|---:|---:|---:|---:|---:|---:|---:|
| 0.10 | **0.821** | 0.553 | **303** | 0.762 | 0.697 | 281 |
| 0.25 | 0.713 | 0.480 | 263 | 0.759 | 0.695 | 280 |
| 0.30 | 0.648 | 0.436 | 239 | 0.759 | 0.695 | 280 |
| 0.50 | 0.287 | 0.193 | 106 | 0.715 | 0.655 | 264 |
| 0.75 | 0.057 | 0.038 | 21 | 0.363 | 0.333 | 134 |

**At a loose IoU threshold the baseline finds more fish than the fine-tuned
model** — 303 true positives against 281, recall 0.821 against 0.762. It then
loses 65% of those finds as the threshold tightens to 0.50 (303 → 106), while
the fine-tuned model loses 6% (281 → 264).

The baseline is not failing to detect fish. It is drawing boxes that do not
match this project's annotation convention: consistently tighter than the
human-drawn boxes. A representative case from `reef_01_00108.jpg` — prediction
`[1004, 195, 1063, 268]` against ground truth `[978, 176, 1086, 277]`, an IoU
of 0.40, correct fish, rejected as a miss at the 0.50 threshold.

What fine-tuning actually bought, therefore, is two things, and detection
sensitivity is not among them:

1. **Agreement with the annotator's box convention** — the flat recall curve
   from IoU 0.10 to 0.50 is the whole story.
2. **Fewer false positives** — 122 against 245 at IoU 0.10, roughly half.

### 7.3 What this means for the study

The defensible claim is narrower than "fine-tuning improves fish detection on
Eastern Pacific reefs":

> Fine-tuning aligned the detector with this project's annotation convention
> and halved its false-positive rate. It did not improve its ability to find
> fish; the general-purpose baseline located slightly more of them.

Three consequences:

- **The improvement may not transfer.** Part of what the model learned is one
  annotator's box-drawing habits, not a property of Eastern Pacific reefs. A
  second annotator, or another dataset, would likely see a smaller gain.
- **mAP50 alone overstates the result** by folding localisation agreement into
  a number that reads as detection quality. The sweep belongs in the write-up
  beside it.
- **The baseline deserves a fairer hearing.** Reported at IoU 0.25 it scores
  F1 0.574 rather than 0.231. Neither figure is wrong; the 0.50 convention is
  standard and should stay the headline, but quoting it without the sweep
  misrepresents where the baseline actually fails.

A worthwhile follow-up: re-score both models against ground truth from a
second annotator on a subset. If the baseline's IoU-0.50 recall rises while
the fine-tuned model's falls, the convention-fitting hypothesis is confirmed
directly.

Raw numbers: `results/test_comparison.json`.

### 7.4 Confusion matrix and per-species recall

From `scripts/confusion_matrix.py`, at conf 0.25 and IoU 0.50. Both models are
single-class, so there is no class confusion to report: the matrix is detection
against background, and the background/background cell is undefined, because a
detector is not asked to enumerate the places a fish is not.

| | Baseline: fish | Baseline: bg | | Fine-tuned: fish | Fine-tuned: bg |
|---|---:|---:|---|---:|---:|
| **predicted fish** | 106 | 442 | | 264 | 139 |
| **predicted background** | 263 | n/a | | 105 | n/a |

These counts reproduce 7.1 exactly from an independent implementation, which
is a check on both.

Every ground-truth box still carries the species the annotator assigned, so
recall can be broken down per species even though neither model predicts one.
This answers a question the detectors' own output cannot: which species get
missed?

| Species | Boxes | Baseline | Fine-tuned |
|---|---:|---:|---:|
| `not_defined` | 209 | 0.167 | 0.617 |
| *Thalassoma lucasanum* | 86 | 0.314 | **0.942** |
| *Azurina atrilobata* | 49 | 0.653 | 0.694 |
| *Stegastes acapulcoensis* | 10 | 0.000 | **1.000** |
| *Bodianus diplotaenia* | 7 | 0.714 | 0.857 |
| *Scarus ghobban* | 5 | **1.000** | 0.400 |
| *Diodon holocanthus* | 3 | 0.667 | 0.667 |

Only `not_defined`, *Thalassoma* and *Azurina* carry enough boxes to support a
claim. The four rows below them hold 3 to 10 boxes each, where a single
detection moves recall by 10 to 33 points — *Scarus ghobban* going 1.000 to
0.400 is five boxes against two, not a finding.

Two things do hold:

- **`not_defined` is the hardest class for both models** (0.167 and 0.617,
  the lowest of the three meaningful rows). That is consistent with those
  being the small, distant or blurred fish the annotator could not identify,
  and it independently supports 4.1: they are genuine fish, harder than
  average, and worth keeping as positives.
- **The fine-tuned model's advantage is concentrated in the abundant classes**
  it saw most during training — *Thalassoma* 0.314 to 0.942 on 86 boxes. On
  *Azurina*, 49 boxes, the two models are near-identical (0.653 against
  0.694), which is a further hint that the gain is convention-fitting rather
  than better detection.

Raw numbers: `results/test_confusion.json`.
